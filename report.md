# Отчёт по первой практике CI

## Проект и workflow

Учебный репозиторий: [cicd-first-run](https://github.com/nikarre/cicd-first-run), ветка `main`.
Файлы из `demo` размещены в корне. Workflow находится в `.github/workflows/ci.yml` и запускается при push в `main`, pull request в `main` и вручную. Тесты перенесены без изменений.

## Прогноз и результат поломки

Прогноз записан до поломки в [prediction.md](https://github.com/nikarre/cicd-first-run/blob/8684b9502144645385fd2693a4f8f6c3b12caa3e/prediction.md).
Ожидалось, что после замены `href="style.css"` на `href="missing.css"` упадёт `test_stylesheet_exists`, а сборка и сохранение артефакта будут пропущены.

Прогноз подтвердился. Из четырёх тестов один завершился ошибкой. Тест проверяет, существует ли подключённый файл стилей. Файла `site/missing.css` нет.

Строка причины из журнала:

```text
AssertionError: False is not true : Missing stylesheet: missing.css
```

Шаг `Run tests` завершился с кодом 1. Шаги `Build site` и `Save site artifact` получили статус `skipped`. По умолчанию они выполняются только после успешных предыдущих шагов, поэтому новый артефакт в красном запуске не был создан.

После возврата `href="style.css"` отдельным коммитом все четыре теста прошли, сборка и сохранение артефакта завершились успешно. Старый красный запуск остался в истории: он проверял другую версию кода.

## Где выполнялись тесты

Тесты выполнялись на runner GitHub Actions — временной машине GitHub с Ubuntu, указанной через `runs-on: ubuntu-latest`. Шаг `Prepare Python` настроил Python 3.12, затем runner получил код нужного коммита и выполнил тесты.

Результат сохранён на GitHub, потому что проверку запустил workflow после push. Журнал и статусы привязаны к запуску и конкретному коммиту, поэтому их можно открыть независимо от локального компьютера.

## Артефакт

`lesson-site` — ZIP с подготовленными файлами из `dist/`: `index.html`, `style.css` и `release.json`.
Артефакт первого зелёного запуска скачан и распакован. В `release.json` проверено:

```json
{"source_commit": "a5827f7ceccdea8229baf55c1fd16a62de831a9a"}
```

Значение совпадает с коммитом первого запуска. Сборка копирует файлы сайта в `dist/` и записывает коммит исходников. Скачивание артефакта не публикует сайт в интернете. В этой практике настроен CI; отдельного шага deploy нет. Срок хранения артефакта в workflow — 3 дня.

## Почему зелёный результат не гарантирует правильность аудитории

До смены аудитории с 301 на 302 ожидалось, что тесты останутся зелёными: номер аудитории в них не проверяется.

После смены аудитории запуск завершился успешно: все четыре теста прошли, сборка и сохранение артефакта выполнены.

Существующие тесты проверяют заголовок вкладки, заголовок h1, наличие файла стилей и текст темы занятия. Они не сравнивают аудиторию с реальным расписанием. Поэтому зелёный запуск показывает только выполнение этих четырёх условий. Если 302 указана ошибочно, текущие тесты этого не обнаружат.
